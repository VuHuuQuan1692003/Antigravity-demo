🔄 Mô Hình Luồng Dữ Liệu Git (Git Lifecycle)

Hiểu rõ vị trí của mã nguồn giúp bạn kiểm soát hoàn toàn câu lệnh cần dùng.

Giai đoạn 1

Working Directory

Thư mục làm việc thực tế trên máy tính nơi bạn đang gõ code và chỉnh sửa tệp.

Giai đoạn 2

Staging Area (Index)

Khu vực chuẩn bị đóng gói các thay đổi trước khi xác nhận lưu lại.

Giai đoạn 3

Local Repository

Kho lưu trữ lịch sử commit ngay trên máy cục bộ (nhánh HEAD).

Giai đoạn 4

Remote Repository

Kho lưu trữ máy chủ từ xa (GitHub, GitLab, Bitbucket) để cộng tác nhóm.

git add <file> Đưa thay đổi từ Working Directory ➔ Staging Area
Chuẩn bị commit
git commit -m "msg" Ghi nhận từ Staging Area ➔ Local Repository
Tạo mốc lịch sử
git push origin <branch> Đẩy từ Local Repository ➔ Remote Repository
Đồng bộ lên đám mây
git fetch / git pull Kéo thay đổi từ Remote Repository ➔ Local / Working
Cập nhật code đồng nghiệp
git restore / checkout Hủy thay đổi tại Working Directory hoặc khôi phục từ commit

📝 Chuẩn Viết Thông Điệp Commit (Conventional Commits)

Quy ước chuẩn quốc tế giúp lịch sử Git rõ ràng, chuyên nghiệp và dễ bảo trì.

feat: <mô tả>
Thêm một tính năng mới cho dự án (feature).
fix: <mô tả>
Sửa một lỗi hoặc bug trong mã nguồn.
docs: <mô tả>
Chỉ cập nhật tài liệu hoặc README mà không đổi code.
style: <mô tả>
Định dạng lại mã (khoảng trắng, dấu chấm phẩy, format).
refactor: <mô tả>
Tái cấu trúc mã nguồn nhưng không đổi chức năng bên ngoài.
chore: <mô tả>
Cập nhật cấu hình build, package npm, công cụ hỗ trợ.
